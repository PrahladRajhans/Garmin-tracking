# Owner-supplied Garmin comparison and analysis links

**Read 23 November 2026.** These sources help identify useful screen interactions,
validation questions and data access patterns. Product pages and tutorials do not
establish physiological thresholds or validate a personalized coaching score.

| Source | What we could verify | What we can use |
|---|---|---|
| [Wellness Project](https://wellnessproject.ai/) and [privacy policy](https://wellnessproject.ai/privacy) | Landing-page metadata describes role-specific coaches and many wearable integrations. The privacy policy explains optional health-data sharing and integration boundaries. Logged-in coaching was unavailable. | Lead with a small question or decision and the readings behind it. Preserve local account handling and explain any optional publish path. |
| [Gneta connector guide](https://www.gneta.app/blog/connect-garmin-to-chatgpt-claude) and [tool comparison](https://www.gneta.app/blog/garmin-data-analysis-tools-2026) | Describes official partner connections, hosting trust tradeoffs and analysis tools. Vendor editorial. Its account of self-hosted routes does not cover this repo's Personal API path. | Maintain clear boundaries between the official personal source, unofficial extras and MCP clients. Validate statements against [Garmin's developer portal](https://developer.garmin.com/gc-developer-program/overview/) and this repo's recorded configuration. |
| [Gneta's readiness study](https://www.gneta.app/research/training-readiness), [VO₂max drift](https://www.gneta.app/research/vo2-max-drift), [race predictions](https://www.gneta.app/research/garmin-race-predictor) | The site's own observational cohort reports a weak median within-athlete readiness/efficiency correlation, frequent small VO₂ estimate changes, and an exponent inferred from Garmin's predictions. That exponent is not measured race performance. | Benchmark the owner's readiness against later similar steady runs. Check changes against sensor and model variability. Retain current race formulas and avoid importing cohort tuning as a personal result. |
| [Kaggle analysis](https://www.kaggle.com/code/kmader/garmin-connect-data-analysis) | Public page supplied title and listed a private data source. The notebook cells could not be inspected in this session. | Keep as an open reference. Reproducible synthetic fixtures can be published for our dashboard and formula tests. |
| [Towards Data Science run analysis](https://towardsdatascience.com/analysis-of-runing-activities-from-garmin-watch-using-python-99609f83314e/) and [companion notebook repo](https://github.com/maxlys/running_data_analysis) | Article walks through export, unit and duration conversion and explores personal training relationships. Repo lists the notebook. | Publish checked unit conventions and compare like-for-like workouts. An individual exploratory injury story does not establish a causal conclusion for someone else. |
| [DEV local Garmin analysis](https://dev.to/arpandesign/local-analysis-of-garmin-activities-and-fitness-data-without-cloud-4cap) and [FIT Dashboard](https://github.com/arpanghosh8453/fit-dashboard) | Article and README describe native FIT parsing, downsampled telemetry, synchronized zoom and a metric-coloured route map. No app installation or data transfer used. | Adopt the shared elapsed-time view and measured point readout in the two overlay pilots. A map tied to time and a local zoom control are candidates if the pair trial proves useful. |
| [Medium running-coach tutorial](https://medium.com/innovating-resourcefully/turn-your-garmin-data-into-a-smart-running-coach-with-python-effdcccaaa84) | Original and canonical short URLs returned HTTP 403. Article claims were not checked. | Revisit with an accessible author edition. |
| [Charpentier's training assistant](https://charpeni.com/blog/visualizing-garmin-data-and-building-a-personal-ai-training-assistant), [garmin-grafana](https://github.com/arpanghosh8453/garmin-grafana) and [Grafana MCP](https://github.com/grafana/mcp-grafana) | Article and companion docs use data-backed dashboard queries to answer route, effort and workout questions. | Use existing target activity and bounded time-window tools to support a short specific answer. Compare routes on local matched data when enough history is available. The app can keep its existing SQLite and offline HTML delivery. |
| [Garmin forum discussion](https://forums.garmin.com/apps-software/mobile-apps-web/f/garmin-connect-web/407430/analytics-analysis) | Users describe grouping by routes/tags, duration-matched rankings and linked distance/pace/month charts. An informal discussion without outcome validation. | A single shared point selector and links from broad views to original experiences are useful design ideas. Consider tag and route filters after coverage verification. |
| [Garmin Health Analysis listing](https://aiskill.market/skills/garmin-health-analysis) | Listing advertises natural-language questions on sleep, Body Battery, HRV and intraday readings. Underlying skill behavior and credential handling are unverified. | Use its example questions to test our own MCP replies. No marketplace skill was installed. |
| [python-garminconnect](https://github.com/cyberjunky/python-garminconnect) | Upstream README lists methods for activity detail, FIT downloads, saved weather, HRV and SpO₂. This repo already uses its unofficial adapter for extras. | Reuse the existing stored weather and data adapters and verify fields against observed payloads. Endpoint names alone cannot guarantee a device captured the field or that an unofficial integration is stable. |
